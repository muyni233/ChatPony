# ChatPony

以《小马宝莉》为主题的 AI 角色扮演平台。TypeScript + Next.js App Router，Bun 管理依赖与任务，Node.js 24 运行后端，SQLite 本地持久化。界面使用纸张、手账批注和克制的墨绿配色，没有预置角色、角色插画、演示账号或 API 服务。

## 直接运行

安装 **Node.js 24+** 和 **Bun 1.3+** 后：

```sh
bun install --frozen-lockfile
bun run dev
```

打开 `http://localhost:3000`。如果端口被占用，可运行 `bun run dev --port 3210` 并访问 `http://127.0.0.1:3210`。无需创建 `.env`。未登录访问首页、对话或后台都会进入登录页面；可主动点击「预览」查看已发布角色。注册、验证与找回密码入口保持开放，开始聊天需要登录。

1. 注册第一个账号：自动成为管理员，跳过邮箱验证。首次身份分配在数据库事务中完成。
2. 在「管理后台 → 站点设置」填写实际站点地址；配置注册开关、邮箱验证和 SMTP。后续用户默认需要验证邮箱，邮件服务尚未配置时会给出明确提示。可在后台主动关闭邮箱验证。
3. 在「模型服务」配置协议、接口地址、API Key 和模型 ID，设定上下文长度与回复预算，启用服务并设为默认。使用「测试连接」验证配置。
4. 在「角色管理」创建人设、介绍、开场白和可选头像，并发布角色。角色才会出现在「发现」与群聊成员选择中。
5. 开始私聊，或邀请 2–6 位角色创建群聊。

站点名称、描述、站点地址、公开注册、邮箱域名限制、邮箱验证、SMTP、模型服务、私有接口许可、5H/1D/7D 配额、公告、会话上限、群聊接话上限、审计保留时间与可信代理配置都保存在数据库中，通过后台修改。环境变量仅用于可选的端口、数据库文件位置等运行参数。

## 已实现的功能

- **账号**：公开注册、首次管理员初始化、登录/退出、过期会话、邮箱验证与重发、密码重置、修改资料与密码、验证后更换邮箱、普通用户注销账号。管理员可分页搜索用户、修改角色和禁用账号，并保护最后一位可用管理员。
- **角色**：后台创建、编辑、排序、发布/下架、删除；可选本地头像、标签、收藏与搜索。没有任何预设角色。
- **私聊**：独立人设、流式回复、停止生成、失败重试、选择模型、场景设定、对话导出、持久化记录。
- **消息显示**：管理员配置 IM 分气泡符号、需要隐藏的原文符号，提供实时预览；流式输出会暂存未完整的控制符，避免闪烁。聊天、列表预览、导出与从消息保存记忆使用同一显示规则。
- **群聊**：普通消息自由发送，使用 `@角色名` 触发回应，角色也能 `@` 其他成员接话。群聊属于创建它的用户，是多 AI 角色场景，不是多用户公共聊天室。
- **长期记忆**：按「用户 + 角色」隔离，可手动添加、从消息保存、编辑和删除；在后续私聊及群聊中注入该角色的上下文。
- **上下文管理**：保守估算中英文 token，预留回复预算，超限时将较早消息整理成摘要，保留最近消息；摘要候选只有在完整回合成功后才提交。原始聊天记录仍然保留。
- **时间与日历**：可选向系统提示词加入日期、时间、星期、农历、当前节气及当天节日；后台选择时区和具体字段，支持预览，默认关闭。
- **管理后台**：使用概览、角色、四协议模型服务、用户与站点设置；SMTP 与模型连接测试；密钥只在服务端解密。
- **次数配额**：5 小时、1 天与 7 天三个独立可选的滚动窗口，全局默认与逐用户覆盖；事务预占避免并发超额，失败/取消返还，聊天与账号页显示余量。管理员可按用户或全站重置选定窗口。
- **公告**：管理员保存草稿、发布、置顶、编辑、撤回与删除；用户查看公告列表和详情，未读状态按账号持久保存，更新后重新提醒。
- **请求审计与统计**：管理员查看对话生成请求、成功/失败/取消/拦截/重放、角色与模型元数据、耗时和配额扣除，支持筛选、分页与每日趋势。
- **可靠性**：错误分类、超时、请求取消、首个 token 前的受限重试、重复发送幂等、会话生成锁、消息与摘要原子提交。
- **适配**：桌面/移动端、键盘操作、弹窗焦点管理、减少动态效果偏好、空状态与错误状态。

## 群聊规则

例如已发布角色「角色甲」「角色乙」加入同一场景：

```text
用户：今天的天气真不错。                  → 只保存消息，不调用模型
用户：@角色甲 你有什么计划？               → 角色甲回复
角色甲：我们去散步吧，@角色乙 你想来吗？    → 邀请角色乙回复
角色乙：当然，@角色甲 我们出发吧。         → 角色甲本轮已回复，不再次触发
```

名字必须与群聊内角色名称一致，并以空格或标点分隔。输入 `@` 会打开角色选择。支持同一条消息提及多位角色，按照出现顺序排队。每次用户触发中，每个角色最多发言一次；默认自动回复总数上限 6、接话层数上限 3，均可在后台调整。新的一条用户触发会开启新的计数。

没有 `@` 的普通消息不需要模型服务。触发 AI 的回合采用原子保存：成功后保存本轮用户消息、所有角色回复和摘要；失败或停止时不保存本轮，已有历史保持不变，界面可重试。

## 分气泡与隐藏符号

在「管理后台 → 站点设置 → 对话气泡与显示」配置：

- **分段符号**默认 `|||`，例如 `你好|||今天过得怎么样？` 会显示为两个连续气泡。留空关闭；支持填写 `\n\n` 按空行分段。该规则会提示给模型。
- **隐藏符号**每行一个，例如 `<control>` 或 `†`，按原文精确匹配，最多 16 个。只隐藏符号本身，不隐藏其包围的文字，也不执行正则或 HTML。默认无隐藏符号。
- 先分段，再隐藏；只处理角色回复，用户消息保持原样。管理员调整后，历史消息也按当前规则显示。数据库与模型上下文仍保留原文，角色之间的 `@` 接话按原文解析。
- 分段不增加模型调用次数或群聊回复轮数。导出 JSON 含清理后的 `content` 及 `bubbles` 数组。

## 配额与注册域名

后台默认启用 **5H 50 次、7D 500 次**；**1D 100 次**默认停用。三个滚动窗口均可独立启停，可以只开其中一个，也可以全部关闭以不限次数。任一已启用窗口用完都会暂时停止 AI 回复。每次用户触发计 1 次，群聊本轮所有角色合计 1 次；开场白和普通群消息不计数。进行中的回复先预占次数，成功后正式计入，失败或取消返还；幂等重试不会重复计数。每笔成功用量分别在 5 小时、24 小时、7 天后离开对应窗口，并非固定整点或每周统一重置。

在「用户管理」点击用户的 AI 配额，可分别覆盖三个上限及开关。限额留空、开关选「继承」时跟随站点默认；只有启用窗口且限额为 0 时才暂停 AI。调整上限、停用配额和删除对话都不会清空已用次数；全部停用时仍保留成功回合历史，重新启用后按窗口统计。账号设置显示成功用量、进行中预占、可用次数与恢复时间。

管理员可通过「重置配额」选择指定用户或全部用户，再选择 5H、1D、7D 或全部窗口。重置只清除所选范围的已用计数，其他窗口、聊天记录和请求审计保持不变。正在生成的回合继续占用预留，完成后计入重置后的窗口，防止重置期间并发超额。

「站点设置 → 注册与账户」可配置允许注册的邮箱域名，每行一个，留空不限制。按域名精确匹配、忽略大小写，子域名需单独列出；首位管理员初始化豁免。该规则仅作用于新注册，已有账号登录、邮箱验证及找回密码保持可用。

请求审计默认保留 90 天，可在后台调整为 7–365 天。统计单位为用户触发的对话请求，群聊一次请求可产生多条角色回复。记录保留必要的业务元数据与固定的错误分类，不保存对话正文或服务密钥；审计与配额数据分别维护，审计记录过期不会重置额度。

## 公告

在「管理后台 → 公告管理」编辑标题和正文，保存草稿或发布。正文以纯文本安全显示并保留换行，不执行 HTML；标题最多 120 字符，正文最多 12,000 字符。可置顶重要公告、撤回到草稿或删除。

登录用户从「站点公告」阅读，列表优先展示置顶内容，导航显示未读数量。打开详情后记录当前版本已读；公告更新或重新发布后会再次显示未读。草稿、已撤回和已删除公告不会向普通用户返回。多人同时编辑使用版本校验，过期的编辑不会覆盖较新的内容。

## 提示词中的时间与日历

在「站点设置 → 时间与日历」开启后，可分别选择日期、时间、星期、农历、当前节气和节日，并设置 IANA 时区（默认 `Asia/Shanghai`）。保存前可预览当前配置实际生成的提示词片段；预览不会保存设置，也不调用模型。默认总开关关闭，原有角色对话不受影响。

日期、时间与星期使用选定时区；中国农历、节气和节日使用明确标注的北京时间历法口径。节气信息描述当前所处节气，不只在交节当天才有内容。节日名称是历法信息，不代表法定放假或调休安排。

每轮用户触发使用同一份实时时间快照，群聊内各角色保持一致；下一轮重新计算。片段计入上下文预算，不直接保存到长期记忆或发给摘要模型。提示词明确将它作为现实时间参考，角色扮演中已设定的时间优先，也不会要求角色在每条回复中报时。

## 四种 API 协议

| 后台协议           | 标准接口                                | 接口地址示例                                       |
| ------------------ | --------------------------------------- | -------------------------------------------------- |
| Anthropic Messages | `/messages`                             | `https://api.anthropic.com/v1`                     |
| OpenAI Completions | `/chat/completions`                     | `https://api.openai.com/v1`                        |
| OpenAI Responses   | `/responses`                            | `https://api.openai.com/v1`                        |
| Gemini Native      | `/models/{model}:streamGenerateContent` | `https://generativelanguage.googleapis.com/v1beta` |

OpenAI Completions 对应常见的 **Chat Completions** 聊天协议，不是已弃用的纯文本 `/completions`。可连接支持这些协议的第三方网关。模型 ID 由管理员填写，不依赖硬编码模型列表。支持流式文本，不发送图像、工具调用或执行模型返回的代码。

接口地址默认阻止回环、内网、保留地址及重定向；自建本地模型时，可在后台明确开启私有地址许可。管理员应配置可信的模型服务。生产部署的出站防火墙可进一步限制元数据和内部服务地址，应用的 DNS 检查不能完全替代网络隔离。

真实 API 和 SMTP 的连通性取决于你在后台填写的服务配置。仓库的协议测试采用本地模拟响应，不消耗付费 API；开发后台的「本地演示回复」开关默认关闭，仅开发环境可用，并在回复中明确标记未调用 AI。

## 生产部署

```sh
bun run build
bun run start --port 3210
```

`start` 使用 Next.js 的 standalone 生产入口，自动复制 `public` 和 `.next/static`。默认监听 `0.0.0.0:3000`；可添加 `--hostname 127.0.0.1` 仅允许本机反向代理连接。Windows、macOS、Linux 使用相同命令。`bun run start --check` 只检查参数和构建，不启动服务；完整参数见 `bun run start --help`。

默认数据库始终为**项目根目录**的 `data/chatpony.sqlite`，加密主密钥也继续使用该目录中的 `application.key`，从开发切换生产不会因 standalone 改变工作目录而新建另一份数据。需要独立数据位置时使用 `--database-path /持久目录/chatpony.sqlite`；相对路径按项目根目录解析。无需业务 `.env`。更多运行参数见 [部署说明](docs/DEPLOYMENT.md)。

也提供 Docker：

```sh
docker compose up --build -d
```

默认容器映射到 `http://localhost:3210`。更改 `compose.yaml` 中的端口映射即可；站点和服务商配置继续在后台完成。

当前架构是**单实例、持久磁盘**部署。SQLite 的 WAL 模式与数据库锁适合中小规模站点；不要将数据放在临时的无服务器文件系统，也不要把同一数据库直接挂载到多台应用实例。需要横向扩容时，应迁移到 PostgreSQL，并把限流和生成任务协调移到共享服务。

公网部署需配置 HTTPS；先完成首次管理员注册，再开放站点入口。后台「站点地址」应与用户访问的完整来源一致，包括非标准端口。反向代理要保留真实 `Host`，关闭聊天流式响应缓冲，并允许最长 660 秒的连接。如果启用「信任反向代理」，代理必须**覆盖**客户端来源 IP 头，且应用端口应仅允许可信代理访问。

Nginx 示例见 [部署说明](docs/DEPLOYMENT.md)。

## 数据、密钥与备份

- `data/chatpony.sqlite`：账号、配置、聊天记录、摘要、长期记忆与加密后的服务密钥。
- `data/application.key`：首次保存机密配置时自动生成的 32 字节 AES-GCM 主密钥。
- 无硬编码密码；密码使用 scrypt 哈希，认证会话使用随机令牌及数据库哈希、HttpOnly/SameSite Cookie。HTTPS 使用 Secure Cookie。
- 数据库和主密钥必须一起备份。丢失主密钥会导致原 API/SMTP 密码无法解密，需恢复密钥或重新保存服务配置。
- 备份应先停止应用，复制整个 `data/` 目录；运行中应使用 SQLite 的在线备份能力，不能只复制可能仍有 WAL 写入的主文件。
- 不要把 `data/`、测试产物、密钥或 `.env` 提交到版本控制。`.gitignore` 和 `.dockerignore` 已排除。

记忆由用户控制，不做未告知的自动画像。删除一条长期记忆不会自动删掉历史消息或已有摘要中的相关文字；需要完全去除时，应同时删除相应对话。角色下架后不再可用于新会话或继续生成，历史记录仍然可查看。

## 开发与验证

```sh
bun run typecheck
bun run lint
bun test
bun run build
```

测试包含四协议请求与 SSE 拆包、取消/超时/重试、上下文预算与摘要隔离，以及使用 Node.js 和真实临时 SQLite 的权限、并发初始化、邮件令牌、幂等、群聊提及与防循环测试。浏览器回归脚本位于 `tests/`，使用 Python Playwright 与本机 Edge；其测试账号和角色仅存在于独立测试数据库，不会填充应用默认数据库。

完整的浏览器回归环境与运行顺序见 [验证说明](docs/VERIFICATION.md)。GitHub Actions 自动运行静态检查、测试与生产构建；Docker 配置需在装有 Docker 的部署环境中验收。

项目结构：

```text
src/app/                 Next.js 页面与 API 路由
src/components/          平台、聊天、账号与管理界面
src/lib/server/          SQLite、认证、后台配置、聊天事务
src/lib/ai/              四协议适配、SSE、预算与摘要
src/lib/types.ts         共享类型
src/styles/              账号和后台样式
tests/                   协议、后端和浏览器测试
scripts/                 后端测试辅助与可选本地管理工具
```

ChatPony 为非官方同人项目，与 Hasbro 无关联。角色内容由站点管理员配置。
